# Docker Practice

## 概要

インフラエンジニアに興味を持ち、Dockerについて学習するために取り組んだ実践プロジェクトです。

Dockerの基本操作から始め、Dockerfileによるイメージの作成、Docker Composeによる複数コンテナの管理、Nginx・Flask・MySQLを連携させた環境の構築まで取り組みました。

学習期間は約2週間です。

最初はDockerの基本的な仕組みを理解するところから始め、実際にコンテナを起動して構成を作り、エラーの原因を調べながら少しずつ理解を深めていきました。

## 学習内容

### 第1章：Dockerfileによるイメージの作成

まず、Dockerの基本となる「イメージ」と「コンテナ」の違いを理解することから始めました。

### 抱いた疑問

> 「コンテナは作り直すと初期状態に戻るのに、Dockerfileの中に `RUN mkdir` のようなフォルダ作成コマンドを書く意味はあるの？」

### 理解したこと

- `docker build` はDockerfileをもとにイメージを作成するコマンド。
- Dockerfileの `RUN` はイメージのビルド時に実行される。
- ビルド時に作成したファイルやディレクトリは、作成されたイメージに含まれる。
- そのイメージから新しいコンテナを起動しても、イメージに含まれたファイルやディレクトリは最初から存在する。

実際にAlpine LinuxをベースにしたDockerfileを作成し、`RUN mkdir` でディレクトリを作成する実験を行いました。

### 直面したエラーとトラブルシュート

<details>
<summary><b>1. Dockerfileのファイル名によるエラー</b></summary>

- **現象：** Dockerのビルド時にDockerfileが見つからないエラーが発生。
- **原因：** ファイル名を `DockerFile` として保存していた。
- **解決：** 標準のファイル名である `Dockerfile` に変更。

```bash
mv DockerFile Dockerfile
```

Linuxではファイル名の大文字・小文字が区別されることを再確認しました。

</details>

<details>
<summary><b>2. イメージ名のスペルミス</b></summary>

- **現象：** 意図したイメージ名でコンテナを起動できなかった。
- **原因：** ビルド時にイメージ名を `ailio-alpine` と入力していた。
- **解決：** `docker tag` を使って正しい名前のタグを付け直しました。

```bash
docker tag ailio-alpine aikio-alpine
```

※実際のコマンドではイメージ名を正確に指定します。

イメージの内容と、イメージに付けられた名前（タグ）は別のものとして管理されることを学びました。

</details>

### 第2章：Docker Composeによる複数コンテナの管理

個別の `docker run` コマンドでコンテナを起動する方法を学んだ後、複数のコンテナをまとめて管理するDocker Composeに取り組みました。

### 抱いた疑問

> 「起動するだけなら `docker compose start` でよさそうなのに、なぜ `up` を使うの？」

### 理解したこと

- `docker compose start` は、すでに作成されている停止中のコンテナを起動する。
- `docker compose up` は、Composeファイルの設定をもとに必要なコンテナやネットワークを作成・起動する。
- `docker compose down` は、Composeによって作成されたコンテナやネットワークを削除する。

それぞれのコマンドは役割が異なり、初回の環境構築では `up` を使うことを理解しました。

### 直面したエラーとトラブルシュート

<details>
<summary><b>1. YAMLファイルのインデントによるエラー</b></summary>

- **現象：** `docker compose up` の実行時にYAMLの構文エラーが発生。
- **原因：** インデントや記述形式が正しくなかった。
- **解決：** `nano` で設定ファイルを見直し、半角スペースを使って階層構造を修正しました。

YAMLではインデントがデータの階層を表すため、スペースの位置が重要であることを学びました。

</details>

<details>
<summary><b>2. portsの記述形式によるエラー</b></summary>

- **現象：** `ports must be a array` というエラーが発生。
- **原因：** `ports` の値をリスト形式ではなく、誤った形式で記述していた。
- **解決：** YAMLのリスト形式に修正しました。

```yaml
ports:
  - "80:80"
```

Composeファイルでは、項目ごとに適切なデータ形式で記述する必要があることを学びました。

</details>

### 第3章：ボリュームを使ったファイルのマウント

Docker Composeの理解を深めるため、ボリュームを使ったホスト側ファイルのマウントにも取り組みました。

### 抱いた疑問

> 「ホスト側のフォルダをコンテナ内にマウントすると、もともとコンテナ内にあったファイルはどうなるの？」

### 理解したこと

- マウントは、ホスト側のディレクトリをコンテナ内の指定したパスから利用できるようにする仕組み。
- ホスト側でファイルを変更すると、マウント先のコンテナからもその変更を確認できる。
- マウント先にコンテナ側のファイルが存在していても、マウント中はホスト側の内容が見えるため、もともとのファイルが見えなくなる場合がある。

実際にNginxの公開ディレクトリへホスト側のフォルダをマウントし、自分で作成したHTMLファイルをブラウザに表示する実験を行いました。

### 直面したエラーとトラブルシュート

<details>
<summary><b>1. システムディレクトリへのマウントによる起動エラー</b></summary>

- **現象：** コンテナ内の `/bin` にホスト側のディレクトリをマウントしたところ、シェルが見つからずコンテナの起動に失敗。
- **原因：** マウントによってコンテナ側の `/bin` にあった実行ファイルが見えなくなっていた。
- **解決：** マウント先を用途に合ったディレクトリへ変更しました。

マウント先によってはコンテナ内の既存ファイルが隠れてしまうため、マウント先の選択が重要であることを理解しました。

</details>

<details>
<summary><b>2. コンテナ側のパス指定によるエラー</b></summary>

- **現象：** `mount path must be absolute` というエラーが発生。
- **原因：** コンテナ側のマウント先を絶対パスで指定していなかった。
- **解決：** `/usr/share/nginx/html` のように、先頭に `/` を付けた絶対パスに修正しました。

その後、ホスト側に作成した `index.html` をNginxから配信し、ブラウザで表示できることを確認しました。

</details>

### 第4章：コンテナのライフサイクル管理

最後に、コンテナの起動・停止・削除の違いについて学びました。

### 抱いた疑問

> 「Ctrl + Cでログ画面を終了した後、コンテナはどうなっているの？ `docker compose down` とは何が違うの？」

### 理解したこと

- `Ctrl + C` は、フォアグラウンドで実行しているComposeの処理に割り込みを送り、コンテナを停止させる。
- `docker compose ps` は、Composeプロジェクトのコンテナの状態を確認する。
- `docker ps -a` を使うと、停止中のコンテナも含めて確認できる。
- `docker compose start` で、既存の停止中コンテナを再起動できる。
- `docker compose down` で、コンテナやネットワークを削除できる。

実際にコマンドを使い分けながら、コンテナが「停止している状態」と「削除された状態」は異なることを確認しました。

## 第5章：NginxとPython Flaskの連携（2コンテナ構成）

Dockerの基本操作を学んだ後、実際に複数のコンテナを組み合わせた環境の構築に取り組みました。

最初の作品では、NginxとPython Flaskを連携させた2コンテナ構成を作成しました。

**作品：** [01_two-containers](./01_two-containers/)

### 構成

| コンテナ | 役割 |
|---|---|
| Nginx | HTMLの配信・リバースプロキシ |
| Flask | APIの処理 |

### 取り組んだ内容

- Dockerfileを使用したイメージの作成
- Docker Composeによる複数コンテナの起動
- Nginxのリバースプロキシ設定
- FlaskによるAPIの作成
- NginxからFlaskへのコンテナ間通信

最初からNginxとFlaskを連携させる構成を目指し、まずは動作する環境を作成しました。

その後、各プログラムや設定ファイルの役割、ブラウザからFlaskまでの通信の流れについて理解を深めていきました。

### 理解したこと

ブラウザからNginxへ送られたリクエストを、Nginxの設定に従ってFlaskへ転送することで、Webサーバーとバックエンドを別々のコンテナとして構成できることを学びました。

## 第6章：MySQLを追加した3コンテナ構成

2つ目の作品では、1つ目の構成にMySQLを追加し、Nginx・Flask・MySQLの3コンテナ構成へ発展させました。

**作品：** [02_three-containers](./02_three-containers/)

### 構成

| コンテナ | 役割 |
|---|---|
| Nginx | HTMLの配信・リバースプロキシ |
| Flask | APIの処理・データベース接続 |

### 取り組んだ内容

- Docker Composeによる3サービスの構成

この作品ではDockerfileを使用せず、Composeファイル内で既存のイメージを指定して環境を構築しました。

### 理解したこと

最初はAIと一緒に動作する構成を作り、その後、MySQLの役割やPythonからデータベースへ接続する仕組みについて理解を進めました。

Flaskが受け取ったリクエストを処理し、MySQLへデータを登録するという、Webアプリケーションの基本的なデータ処理の流れを実践しました。

また、MySQLコンテナへ接続し、SQLを実行して登録されたデータを確認しました。

## AIを活用した学習

今回の学習では、AIを質問やエラー調査のための学習補助として活用しました。

エラーが発生した際には、エラー画面のスクリーンショットや関連するコード・設定ファイルを共有し、原因の調査と修正を進めました。

また、単にエラーを解決するだけでなく、以下のような疑問についても質問しました。

- 現在どのコンテナ環境で操作しているのか

- FlaskからMySQLへ接続する仕組みはどうなっているのか

動作する構成を作った後も、実際の環境やプログラムを確認しながら理解を深めることを意識しました。
