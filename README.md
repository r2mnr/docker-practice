#  第1章：Dockerfile による「オリジナル型（イメージ）」の鋳造

まず、Docker の最も深い核心である**「イメージ（クローン元の型）」**と**「コンテナ（使い捨ての部屋）」**の構造的な違いを理解することからスタートしました。

### 💡 抱いた疑問
> 「コンテナって毎回起動時に初期状態へリセットされるはずなのに、設計図（Dockerfile）の中に `RUN mkdir`（フォルダ作成）なんてコマンドを書く意味はあるの？」

### 🧠 解き明かした仕組み
*   `docker build` コマンドは、使い捨ての部屋を作っているのではない。
*   `RUN` コマンドは、部屋が起動したあとではなく**「クローン元の型（イメージ）を作る工事中」**に実行され、型そのものにその模様をガチッと彫刻（固定）している。
*   だからこそ、出来上がったオリジナルの型（`aikio-alpine`）から起動した部屋には、何度使い捨ててリセットしても、最初から作成したフォルダ（`aikio_dir`）が永久に存在し続けるという構造を見抜いた。


### 🛠️ 直面したエラーとトラブルシュート

<details>
<summary><b>1. ファイルの命名規則による「そんなファイルは無い」エラー</b></summary>

*   **現象:** 完璧なコマンドを打ったはずなのに、Dockerから `No such file or directory` と怒られた。
*   **原因:** ファイル名を `Dockerfile` とすべきところ、真ん中の `F` を大文字で保存してしまっていた。Linux/Dockerの世界は大文字・小文字を厳格に区別し、オプションなしのビルド（`.`）では世界共通ルールである `Dockerfile`（最後は小文字）という名前を決め打ちで自動検索しに行く仕様であることに気づいた。
*   **解決:**
    ```bash
    mv DockerFile Dockerfile
    ```
    名前を正確に修正し、無事に自動工事を成功させた。

</details>

<details>
<summary><b>2. スペルミスによるイメージ名の修正（docker tag の裏ワザ）</b></summary>

*   **現象:** `docker build` 時のスペルミスで、型が `ailio-alpine`（`k` が `i`）という名前で登録されてしまい、大正解の名前で `run` しようとするとエラーになった。
*   **原因:** Dockerの型は上書き変更（`mv` のような操作）ができない。
*   **解決:** プロの現場でも使われる裏ワザ `docker tag ailio-alpine aikio-alpine` を実行。中身のデータを複製することなく、新しい正しい名札（タグ）だけをペタッと貼り直す仕様を学び、古い型は `docker rmi` で美しく削除した。

</details>


#  第2章：Docker Compose による「配置・運営指示書」への進化

個別のコンテナを長いコマンドで1つずつ立ち上げる限界を知り、システム全体のレイアウトを1つの設定ファイルに記述して一撃で一斉起動する「Docker Compose」へステップアップしました。

### 💡 抱いた疑問
> 「起動するだけなら `docker compose start` でよさそうなのに、なぜわざわざ `up` というコマンドを使うの？」

### 🧠 解き明かした仕組み
*   `start` は「すでにそこにある部屋の電源（ブレーカー）をオンにするだけ」のコマンド。
*   `up` は「まだこの世に部屋が存在しない空き地の状態から、『指示書（yml）』を元に、材料をネットから集めて部屋（コンテナ）をゼロから建築し、電源を入れるまでをすべて全自動で行う」コマンドであるため、最初の起動には `up` が必須であるという決定的な違いを理解した。

### 🛠️ 直面したエラーとトラブルシュート

<details>
<summary><b>1. YAMLファイルの「半角スペース（インデント）」の罠</b></summary>

*   **現象:** `docker compose up` を実行した際、`mapping values error` が発生。
*   **原因:** YAMLファイルは全プログラミングの技術の中でトップクラスにスペースの数に厳しく、1文字のズレや全角スペースの混入で構造がパニックを起こす仕様であるため。
*   **解決:** `nano` で全ての行のスペースを一度デリートして左詰めにした上で、半角スペースだけを使って正確に美しい階段状の段差を作り直した。

</details>

<details>
<summary><b>2. 記号ミスによる「配列（リスト）形式」の違反エラー</b></summary>

*   **現象:** `ports must be a array`（ポートは配列形式で書いて！）とDockerに怒られた。
*   **原因:** 複数指定ができる項目（`ports:`）の記述に、誤って `=`（イコール）の記号を使ってしまっていた。
*   **解決:** イコールを削除し、YAMLの世界で「ここからリスト（配列）形式がスタートするよ」と大工さんに伝えるための世界共通マークである `- `（ハイフン ＋ 半角スペース）に書き換えることで、一撃起動を成功させた。

</details>

#  第3章：ボリューム（-v）を用いたComposeによる「画面ジャック（リアルタイム同期）」

Docker Composeをさらにプロ仕様へ発展させるため、コンテナの最大の弱点である「使い捨て（リセットされる）」に対応する「ボリューム（データ保存・共有機能）」を組み込みました。

### 💡 抱いた疑問
> 「コンテナを volumes で繋いだ瞬間、コンテナの内部にあった元の表示用ファイル（Welcome to nginx!）はどうなっちゃうの？」

### 🧠 解き明かした仕組み
*   ボリュームの接続（`- 大本:コンテナ`）は、ファイルをコピーしているのではない。
*   ホスト（Ubuntu）側のフォルダを、コンテナの中のNginxが画面データを読み込む専用の部屋（`/usr/share/nginx/html`）へ直接ガチッと連結し、「上映スクリーン」そのものを乗っ取る（ジャックする）技術であることを見抜いた。
*   そのため、大元のフォルダに何も指定しない状態（`index.html` が無い状態）で立ち上げると、文字化けではなく「表示するものが何も無い！」とNginxが門前払いをして `403 Forbidden` エラーを出すという、Webサーバーの厳格な初期設定の動線を突き止めた。

### 🛠️ 直面したエラーとトラブルシュート

<details>
<summary><b>1. マウント先の勘違いによる「コンテナ破損エラー（/bin の上書き）」</b></summary>

*   **現象:** 最初、ボリュームの連結先をコンテナの中の `/bin` に指定したところ、黒い画面を起動する `sh` が見つからないという致命的なエラーが発生した。
*   **原因:** システムの重要な実行ファイル（プログラム本体）が詰まっている場所に大元の空のフォルダをマウントしたため、コンテナ側の重要データが丸ごと非表示化（上書き）されてコンテナが壊れてしまった。
*   **解決:** ボリュームを繋ぐときは、上書きされても安全な空の部屋（`/mnt`）や、アプリ専用の公開フォルダ（上記）をピンポイントで狙ってワイヤーを結ぶのが絶対の鉄則であることを、身をもって実証した。

</details>

<details>
<summary><b>2. コロンの右側の指定ミス（絶対パスのルール）</b></summary>

*   **現象:** `mount path must be absolute` と怒られて起動に失敗。
*   **原因:** コロン（`:`）の右側（コンテナの中の住所）を、`/usr/share/...` とスラッシュなしで書き始めてしまっていた。
*   **解決:** Linuxの絶対のルールである「最上層（ルート）から始まるフル住所にするために、頭に必ず `/` をつける」に従い、`:/usr/share/...` に修正。
*   **結果:** 初日に学んだ文字コード（UTF-8）の宣言を含んだ自作の `index.html` をホスト側に置くだけで、コンテナを一切いじることなく、ブラウザの画面がリアルタイムに自分オリジナルの「Hello Aikio!」サイトへ一撃で切り替わる、最高の開発環境を開通させた。

</details>

#  第4章：インフラエンジニアの命である「運命管理（ライフサイクル）」の完全理解

最後に、動かしたサーバーをお片付けする場面で、インフラの最も重要な「見えない落とし穴」を暴き出しました。

### 💡 抱いた疑問
> 「`Ctrl + C` でログ画面を抜けたあと、`docker compose ps` を打っても空っぽ（非表示）になるのはなぜ？ `Ctrl + C` と `docker compose down` って何が違うの？」

### 🧠 解き明かした仕組み
*   `docker compose ps`（オプションなし）は、「現時点で元気に起きている（電源ONの）コンテナ」しか表示してくれないという仕様の罠があることを見抜いた。
*   `Ctrl + C`（一時停止）：映画館の営業を終了し、電気を切って鍵を閉めただけ。建物も専用の光回線もそのままモールの中に残っているため、`docker ps -a`（すべての歴史を表示）を打つと `Exited` というお休み状態でしっかりと残骸が確認でき、`start` 一発で1秒で営業再開できる。
*   `docker compose down`（完全解体）：ショベルカーを持ってきて、建物ごと跡形もなくぶっ壊し、敷いた回線もすべて引き抜いて完全な更地（リセット）に戻す作業。
*   パソコンのメモリや回線の通り道を無駄に占有し続けないために、実験終了後は必ず `down` を実行して、環境を美しく更地に戻すのがインフラエンジニアの絶対の鉄則（マナー）であることを、自分のコマンドを使って完璧に証明した。
